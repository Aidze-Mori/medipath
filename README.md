# MediPath

**От результата исследования — к понятному следующему шагу.**

MediPath — наш веб-проект для хакатона. Он помогает пациенту разобраться в медицинском документе и собрать план посещений, а сотруднику клиники — увидеть результаты пациента и подготовить предложение записи.

[Открыть демо](https://medipath-jury.netlify.app/patient)

## Что можно попробовать

- Загрузить PDF, фотографию, TXT или DOCX. Текст извлекается в браузере; для сканов есть OCR на русском и английском.
- Сверить разделы документа с оригиналом и подтвердить текст перед обработкой.
- Получить краткое пояснение с раскрываемыми разделами и цитатами из документа.
- Собрать план по нескольким исследованиям. Направления к одному специалисту объединяются в один визит.
- Подобрать учебного врача по цене, полу, метро и расстоянию, выбрать время, завершить план и скачать события календаря.
- Открыть рабочее место клиники: список пациентов, их документы, статусы, план посещений и предпросмотр уведомлений.

Это прототип. Врачи, пациенты, цены и записи в демо вымышлены. Настоящая запись в клинику и отправка SMS/push не подключены.

## Быстрый запуск

Нужны **Node.js 24** и npm. Подойдут Windows, macOS и Linux.

```sh
git clone https://github.com/Aidze-Mori/medipath.git
cd medipath
npm ci
npm run prepare:assets
```

Запустите API:

```sh
npm run dev:api
```

Во втором терминале, в этой же папке:

```sh
npm run dev
```

Откройте [http://127.0.0.1:5173/patient](http://127.0.0.1:5173/patient). Рабочее место клиники находится по адресу `/clinic`. Для остановки сервера нажмите `Ctrl+C` в терминале.

**Без API-ключа сайт тоже запускается:** доступны загрузка документов, OCR, локальный разбор и подготовленные сценарии. Внешние запросы к AI при этом не выполняются.

## Три сценария для жюри

Нажмите **«Демопанель»** в правом нижнем углу. Там же находятся переключение между пациентом и клиникой, информация о текущей сессии и настройки демонстрации.

1. **Результат из «Третьего Мнения».** Учебное уведомление открывает готовое исследование без загрузки файла. Можно посмотреть пояснение и предложение следующего шага с клиническим источником. Это имитация входящих данных, а не подключение к реальному сервису.
2. **Большой отчёт врача.** Двухстраничный PDF проходит настоящее извлечение текста, сверку и обработку. Затем можно собрать план по явному направлению из документа. Без настроенного AI используйте «Открыть PDF без внешнего AI».
3. **Срочный результат.** Показывает документ с прямым указанием обратиться за экстренной помощью. Система сохраняет это указание и не предлагает обычную плановую запись.

Демо и рабочая сессия разделены. Повторный запуск, смена сценария и сброс доступны в демопанели. Данные живут в памяти вкладки: после обновления страницы их нужно загрузить заново.

## Как подключить AI

Создайте файл `.env` по образцу `.env.example`. Укажите собственный ключ и доступную модель:

```dotenv
LLM_PROVIDER=openai
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=your_model_here
OPENAI_BASE_URL=https://api.openai.com/v1
ALLOW_LOCAL_LIVE=1
ALLOW_ANONYMIZED_DOCUMENTS=1
```

Перезапустите `npm run dev:api`. Сервер использует Responses API со структурированным JSON-ответом. Поддержаны прямой OpenAI и VseLLM; для VseLLM укажите `https://api.vsellm.ru/v1` и название модели с префиксом `openai/`. На демостенде проверена модель `openai/gpt-4.1`. Модель задаётся серверной переменной, поэтому её можно заменить без изменения интерфейса.

Ключ не нужен браузеру и не должен попадать в исходники. Файл `.env` исключён из Git. Для локальной разработки также есть provider `codex_cli`: нужны установленный CLI, его авторизация, `LLM_PROVIDER=codex_cli` и `CODEX_MODEL`.

### Что отправляется модели

Сначала пользователь проверяет распознанный текст. Затем браузер оставляет медицинские разделы и маскирует распознаваемые идентификаторы пациента. Сервер повторяет очистку перед запросом к модели. Сам файл, его название и отдельные поля с данными пациента в AI-запрос не включаются.

В ответе проверяются структура, ссылки на исходные цитаты, числа и соответствие редакции документа. Непрошедший проверку ответ не показывается как готовый результат. При сбое есть повтор запроса.

Очистка построена на правилах и регулярных выражениях: это не гарантия полной анонимности. Пояснение не является диагнозом. Для произвольных документов маршрут использует явные указания исходника; клинические предложения ограничены подготовленными демосценариями и не означают универсальную систему диагностики.

## Сборка и проверки

```sh
npm test
npm run typecheck
npm run lint
npm run verify:corpus
npm run build
npm start
```

После `npm start` готовая сборка доступна на [http://127.0.0.1:3001/patient](http://127.0.0.1:3001/patient).

Для браузерных тестов нужен установленный Google Chrome:

```sh
npm run test:e2e
```

Проверка production-сборки с извлечением PDF и OCR:

```sh
npm run smoke:production
```

## Netlify

В репозитории уже есть `netlify.toml`:

- build command: `npm run build`;
- publish directory: `dist`;
- серверные функции: `netlify/functions`;
- API и прямые адреса `/patient`, `/clinic` настроены через redirects.

Ключ и модель задаются в environment variables проекта Netlify, со scope Functions, а не во frontend. Для облачного анализа загруженных документов нужны `ALLOW_CLOUD_DOCUMENTS=1` и `ALLOW_ANONYMIZED_DOCUMENTS=1`. В облаке используйте `LLM_PROVIDER=openai`, `ALLOW_LOCAL_LIVE=0`.

Для небольшого показа можно включить `DEMO_WITHOUT_REDIS=1`. В этом режиме общего лимита запросов приложения нет. Без него нужны `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Codex CLI на Netlify не запускается.

## Устройство проекта

```text
src/app             оболочка приложения и навигация
src/features        загрузка, кабинет пациента, клиника, запись, демопанель
src/domain          документы, редакции, планы и учебные данные
src/engine          правила маршрута и проверка оснований
src/privacy         минимизация данных и проверка ответов
server              общий серверный слой и AI-провайдеры
netlify/functions   HTTP-функции для Netlify
data                разрешённый учебный корпус и примеры
public/examples     синтетические документы для демонстрации
tests               unit- и браузерные тесты
scripts             подготовка ресурсов, проверки и упаковка
```

Интерфейс: React, TypeScript, Vite. PDF: PDF.js. OCR: Tesseract.js. Проверки: Vitest и Playwright. Отдельной базы данных в этой версии нет.

В репозитории нет личных медицинских документов и ключей команды. Происхождение учебных тестовых файлов указано в `tests/fixtures/document-intake/manifest.json`; сведения о шрифтах и иконках сохранены в `docs/design/assets`. Полные сторонние клинические архивы в поставку не включены.
